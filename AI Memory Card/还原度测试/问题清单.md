### 1. 强制对齐后验阈值 0.5 未标定（参数标定）

判「可疑」的后验阈值，直接影响判错率。当前是经验值，没多样本验证。

**位置**：`compare_phoneme.py` `classify_verdict` 的 `threshold=0.5`。

**怎么标定**：录 20~30 个"读对/读错"已标注的词，扫阈值 0.2~0.8（步长 0.05），选判错率最低的值。

### 2. `AGG_POWER=3.0` 未标定（参数标定）

节奏分幂平均的指数（对局部错误敏感度），n=1 数据不够定。

**位置**：`compare_rhythm.py` `AGG_POWER = 3.0`。

**怎么标定**：录 10~15 段节奏好坏分档的句子，扫 p ∈ {1, 1.5, 2, 3, 4, 5}，选机器节奏分排序最接近人工排序的 p。

### 3. 重音音高路双向未标定（参数标定，n=1）

音高路双向（升调/降调都算 prominence），gap<0 分不清「原声降调重读」还是「你没抬」。句末降调 vs prominence 需多样本听辨。

**位置**：`compare_rhythm.py` `_cue_advice` 音高分支（gap<0 走中性措辞）。

### 4. 安装 emphases 作为重音标尺（2026-10-31 大法师拍板要装）

**是什么**：`emphases`（Georgia Tech interactiveaudiolab，ICASSP 2024，`pip install emphases`）——一个现成的**单词重音（prominence）识别模型**。输入**音频波形**（文本只用于强制对齐定位每个词），用神经网络从声学特征判断每个词"母语者听起来重不重"，输出逐词 prominence 分数。**靠声学信号判断，不是靠词义/句式**。

**神经网络判断重音的方式（论文已查清，接手者不用再查）**：
1. **输入 = 80 通道 log-mel 频谱**（每帧 10ms，hop 160 采样点 @16kHz）。把音频转成"时间×频率"热力图。
2. **只靠频谱，不显式算音高/响度/时长** —— 论文原文："加了音高、周期、响度特征没有任何提升，它们与频谱冗余"。音高体现在频谱的谐波结构、响度体现在能量、时长体现在时间轴，网络自己从频谱里学"重音长什么样"。这回答了"不通过语调怎么判断重音"：它不显式计算语调，而是让 CNN 从频谱隐式学。
3. **网络 = 6 层卷积（CNN）**，80 通道、kernel 3、ReLU；帧级编码器 + 词级解码器。论文对比过 Transformer，结论是卷积更好。
4. **核心机制 = 帧→词的可变步长下采样**：把属于某词的几十帧汇总成该词一个分数（average/max/sum/center 四种，最优组合 Pearson 相关 0.675）。
5. **词边界靠强制对齐提供**（P2FA）—— **你们项目已有音素级强制对齐能力**，理论上可直接喂给它。

**为什么装**：它是「母语者感知重音」这个**真值**的现成标尺。现在的邻域法（音高半音/响度÷中位/时长÷中位三路投票）是手写启发式，只是**假设**这三条规则≈母语者感知；emphases 用真人母语者众包标注训练，直接给真值。装它的用途 = 校验邻域法准不准，尤其能帮任务 3（重音音高路）解决"降调重读"判定。

**关键洞察（写进决策依据）**：论文"音高/响度/时长冗余、频谱就够"的结论，反向提示你们邻域法"手写 3 个显式特征"未必是唯一正确路线——但手写 vs 网络自动学谁更准，**没对比过**，这正是装 emphases 做对比的价值。对比结果直接决定邻域法要不要保留/降级。

**怎么用**（原计划 09-22 决策 7，10-12 因"未在 L2 验证+离线倾向+n=1 上限低"暂缓，现升格）：
1. `pip install emphases`（需拉 torchaudio + 联网下模型 `maxrmorrison/emphases` 的 `model.pt`）
2. 对现有那对音频跑一次，看它判的"原音频突出词"跟人工听的是否一致
3. 与邻域法**逐词对比**：接近 → 邻域法够用（零依赖、可解释）；差很多 → 改用 emphases 或两者都出
4. 用它当任务 3 的多样本真值来源：喂一批"升调重读/降调重读"标注音频，标定音高路方向
5. 因项目已有强制对齐，可尝试用 `from_alignment_and_audio` 直接喂项目自己的词边界，省去装 HTK/P2FA（README 默认要装 HTK，很重）

**许可证（09-23 已核实）**：代码 MIT；模型权重 CC BY 4.0（**无 ShareAlike，不传染**）。见归档区"任务 15"。

### 8. 实现「去背景音」功能（2026-10-31 新增，方案未定，需先调研）

**需求**：用户录音可能带背景噪声/背景音乐/他人说话，直接评测会污染音素识别与节奏/重音分析。目标是在评测前把"目标人声"从背景里清理出来。

**⚠️ 方案未定，别预设"一定要上重模型"**：大法师本地装了 UVR5，但 UVR5 这类深度学习分离模型普遍**模型大、CPU 慢**（几秒录音要几十秒），对"一键跑"体验伤害大。**可能有不依赖重模型的更快/更轻办法**，接手者应先评估以下路线再定：

**候选方案（按"轻→重"排序，先试轻的）**：
1. **轻量降噪/去混响**：`noisereduce`、`deepfilternet`、RNNoise、谱减（spectral gating）等——只去背景噪声，不做人声/伴奏分离，几十 MB 内、CPU 实时，可能已够用（如果用户场景主要是"有噪声"而非"有背景音乐/他人说话"）
2. **经典信号处理**：维纳滤波、谱减法、自适应滤波——零依赖，但只对平稳噪声有效
3. **UVR5 深度学习分离**（重，兜底）：只在"背景有人声/音乐"这种轻量法搞不定的场景才上，且做成可选开关
4. 其他：`spleeter`（Deezer，2/4/5 stems，比 UVR5 轻但已停维护）、`Demucs`（Meta，质量高但更重）

**关键判断点（接手者先想清楚再动手）**：
- 用户的真实场景到底是"安静房间+少量噪声"（→ 轻量降噪就够）还是"嘈杂环境/背景音乐"（→ 才需要真分离）？
- 这决定走轻量还是重模型，**方向错了会白做**

**要做**：
1. 先明确用户场景（问大法师或看已有素材的噪声情况）
2. 按"轻→重"试：先 noisereduce/deepfilternet 这类轻量降噪，跑一版看对评分的影响；不够再上 UVR5
3. 无论哪条路，都只做**评测前预处理一步** + 可选开关（默认关），不改下游评分逻辑
4. 若最终要上 UVR5：接入方式（本机 CLI vs `uvr-headless-runner`）+ 模型选型 + 权重许可，见归档备注

**建议顺序**：先定场景 → 先试轻量降噪 → 不行再评估 UVR5 → 拍板接入。
