## 零、数据正确性（换素材必踩，最高优先级）

### 任务 0：原音频缓存没有失效检测

**问题**：换原音频后，`audio\原音频\原音频缓存.json` + `原音频_logits.npy` **不会自动失效**。
`run_all.py` 的 `ensure_reference()` 只查 `os.path.exists(REF_CACHE_JSON)`，文件在就跳过转写。
参考音素表有「比音频新」的过期检测，但**原音频缓存和 logits 没有**（10-28 拆缓存后的隐患）。

**后果**：换了原音频但没手动删缓存 → 用旧原音频的参考音素/logits 去评测新模仿音频，结果完全错乱且不报错。

**要做**：
1. 缓存里存原音频的 mtime / 大小 / hash（或比对缓存生成时间 vs 原音频文件 mtime），不一致就报「原音频已换，请重新跑 分析原音频.bat」并拒绝用旧缓存
2. `原音频_logits.npy` 同理（或与缓存联动）
3. 最好在 `ensure_reference()` 里自动检测并阻止，而不是依赖用户手动删缓存

## 一、评分口径（影响准确率，优先级最高）

### 任务 1：删除 difflib 序列比对算法（音变分也改强制对齐）

**为什么删（原因，务必先理解再动手）**：
difflib 序列比对有**严重的对齐错位假象**，导致「替换 / 缺失 / 多余」三类划分全部不可靠：
- 实测：`computers` 被标「多读 7 音」（`iː d æ s aʊ s ɚ`）、`lessons` 被标「多读 8 音」——都是**整词对齐错位**，不是真多读
- `travel → agency` 被标「漏读 9 音」——整段错位
- 大块替换两边长度不等（如 `in → a 之间`：应读 `n ɐ`、实读 `ɪ ə tʃ ɑː w ɛ`）
- 记忆早有记录：「46% 的替换音来自 9 个错位大块」

**现状**：发音分已改用强制对齐（10-29 完成），音变分还挂在 difflib 上，是同类残留。

**要做**：
1. 删 difflib 对齐代码（`compare_phoneme.py` 对齐逻辑、`classify_diffs`、`align_l2_pairs` 等）
2. 音变分「缺失」改用强制对齐「没读出来」（后验低 = 没读出来，可靠）
3. 「多余」项重定口径：difflib 的「多余」是假象、强制对齐又算不了多余音（单向定位）→ 需决策丢/降权/其他（建议先丢，标注已知局限）
4. 报告 difflib 口径段（「二、音变+发音纠音 difflib 口径」）一并处理
5. 母语者基准统一：现在两个口径并存（difflib 相似度 88.8 + 强制对齐可疑 37 处），删 difflib 后统一到强制对齐口径
6. `SCORE_VERSION` +1

**注意**：当前工作区有 3 个未提交文件（`build_align_stat` 分母笔误修复、SCORE_VERSION=6、selftest +5 例），删 difflib 会覆盖/重构这部分，接手时先 `git status` 看现状。

## 二、功能缺失

### 任务 2：单句模式加「转文本 + 原文本对比 + 单词级纠音」—— ✅ 已完成（10-30）

**需求**：单句模式转写用户音频成文本，和「原文本」（参考答案）对比，做**单词级纠音**（「你把 Thanks 读成了 Sanks」「你漏了 for 这个词」）。

**已实现**（`compare_long.py` + `xunfei_transcribe.py`）：
- 转写「模仿」音频 → `transcript_fix` 修复 → 与原文本**整段词级对齐**（跨句拼词序列，非按句号切），按原词所属句号归组。
- 对齐用 `SequenceMatcher`（`align_words`，忽略大小写），输出读对/读错/漏读/多读四类。
- 报告加「三、单词级纠音」段；纯展示、不参与评分（综合分不变）。
- 代价：每次评测多调一次讯飞转写（约 13s + 额度），失败自动降级跳过。
- selftest +16 例（270/270）。

### 任务 3：转写确认环节（人工兜底，原「坎 3」）—— ✅ 已完成（10-30）

**说明**：标点模型已引入并生效（断句解决、16 句正常），主体完成。剩下的是「转写确认」人工兜底环节（独立坑）。

**已实现**（`analyze_reference.py` 新增 `confirm_transcript()`）：
- 标点恢复后、生成参考音素表前，把转写文本写到 `audio\原音频\转写文本_待确认.txt`，用 `os.startfile` 自动打开默认编辑器让用户改，保存关闭后轮询读回（内容 30s 不变即视为确认）。
- 兜底两类自动修不掉的错：①标点模型误判 ②讯飞听错词（it'ss→it's a）。
- 待确认文件**每句一行**展示（`split_lines`），读回时 `_collapse` 压回单行，不影响后续生成参考音素表。
- 是否重弹由 `should_reconfirm(existing, text)` 决定：内容与本次转写一致 → 不重弹直接用；不一致（换过原音频/上次改过）→ 重新弹确认。
- 跳过开关：环境变量 `AUTO_CONFIRM=1` 或命令行 `--auto`（无人值守/批量重跑不卡住）。
- selftest +8 例（278/278）。

### 4. 强制对齐后验阈值 0.5 未标定
判「可疑」的后验阈值，直接影响判错率。当前是经验值，没多样本验证。

### 5. `AGG_POWER=3.0` 未标定

## 四、技术债（产品化前清，不阻塞）

### 8. 短块噪声
CTC 帧下 `oh`/`im`/`are` 仅 1-3 帧，2 词连读块分母仍小，主导节奏分（32.8 偏低）。

### 9. beam search 有 bug
自写 prefix beam search 输出 1610 音（明显错）。要用必须先修好或装 pyctcdecode + kenlm（当前都没装）。

### 10. 重音角色分组空转（P2）
参考音素.json 全部 150 词角色都是「A」。多人对话素材最需要分组，但讯飞转写不返回说话人标签 → 自动路由拿不到角色。需在转写文本用 `A:`/`B:` 标注说话人或提供角色映射文件。

### 11. P3 小项
`compare_long.py` 对同一音频 `load_mono` 各调 2 次（浪费 ~0.5s）；`logkit.py` 的 `_READY`/`_TAG` 是死代码。
