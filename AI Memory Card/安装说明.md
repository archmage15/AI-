# AI 录音卡 · 语音评测测试包 —— 安装与使用说明

> 本文件写给**第一次拿到这个包的人或 AI 助手**。
> 照着从头做到尾，就能把四个测试脚本跑起来。
> 每一节末尾有「✅ 成功的样子」，对不上就先看最后一节的「排坑」。

---

## 0. 这个包是干什么的

一个**英语口语评测的技术验证包**，用来回答一个问题：

> 学生跟着原音频模仿英文，AI 到底能不能指出「哪里发音不对、哪里音变没还原、哪里节奏不对」？

包里有 4 条测试线路，可以分别验证：

| 文件夹 | 线路 | 判断什么 | 需要什么 |
|---|---|---|---|
| `发音评测测试\` | 微软 Azure 发音评测 | 逐**音素**打分，标出读错的音 | Azure 密钥 |
| `讯飞评测测试\` | 讯飞 ISE 流式评测 | 音素 + **连读/重读/停顿/升降调**检错 | 讯飞密钥 |
| `还原度测试\` | 音频对音频对比 | 我的模仿 vs **原音频**，差在哪个音 / 节奏像不像 | 两段 wav |
| `语音转文字\` | Azure 实时转写（早期链路） | 说了什么（**不含**发音判断），另有麦克风排查工具 | Azure 密钥 |

**核心概念（先看懂这两个词，后面就顺了）**

- **发音评测 ≠ 语音转文字**。转写只告诉你「说了哪些词」，判不出「说得准不准」。
  判断准不准，要的是**发音评测**，它会逐音素（音标）打分。
- **音素**：把一个音节拆到最小单位，比如 `pronunciation` = `p ɹ ə n ʌ n s i eɪ ʃ ə n` 共 12 个。
  发音评测就是给这 12 个音逐个打分，低于阈值的标出来 —— 这就是「指出哪里不标准」的依据。

## 1. 装 Python（只需做一次）

**要求：Python 3.11 或更高。**（本包在 3.13 上验证通过）

1. 打开 https://www.python.org/downloads/ 下载最新版 Windows 安装包。
2. 运行安装包，**第一屏底部务必勾选 `Add Python to PATH`**。

> 这一步漏了后面全废。装完可以验证：按 `Win + R`，输入 `cmd` 回车，在黑窗口里敲
> ```
> python --version
> ```
> 能打印出 `Python 3.1x.x` 就对了。

**✅ 成功的样子**：`python --version` 有版本号输出，不是「不是内部或外部命令」。

## 2. 一键装依赖

**双击包根目录的 `install_deps.bat`。**

它会自动做四件事：

1. 找到你刚装的 Python
2. 在本文件夹建一个**独立的**环境 `.venv`（不会污染系统里其他 Python）
3. 走**清华镜像**装依赖（比官方源快很多）
4. 自检：能不能 import 关键库

> **为什么用镜像**：PyPI 官方源在国内经常超时，报错长这样
> `Could not find a version that satisfies the requirement ... from versions: none`。
> 看到这个错，就是网络问题，不是包的问题。

**✅ 成功的样子**：最后打印
```
[4/4] self-check: importing key libraries ...
      all OK
      torch 2.14.0+cpu

============================================================
   DONE
============================================================
```

**装到一半断了怎么办？** 直接**再双击一次** `install_deps.bat`。pip 会跳过已装好的，从断的地方继续。

**这步最慢，正常耗时 3–10 分钟**（`torch` 一个就约 200MB）。

## 3. 填密钥（按你要测的线路选填）

包里**不含任何密钥**，所有密钥都留了占位符，需要自己填。
每个脚本都支持**三种填法，任选一种**：

**填法 A：建 `keys.txt`（推荐，最省事）**

在每个测试文件夹里建一个 `keys.txt`，内容两行：

```
key=你的密钥
region=eastasia
```

即：
- `发音评测测试\keys.txt`
- `语音转文字\keys.txt`
- （讯飞的字段名不同，见下面 3.2）

**填法 B：设环境变量**（适合给 AI 或批处理用）

```
AZURE_SPEECH_KEY=你的密钥
AZURE_SPEECH_REGION=eastasia
```

**填法 C：直接改脚本**（最不推荐，容易误发给别人）

打开 `.py`，找到 `SPEECH_KEY = "在这里填你的KEY"`，把引号里替换掉。

> ⚠️ **填法 C 有泄露风险**：脚本一旦被转发、上传、进 Git，密钥就流出去了，别人能用你的额度。
> 所以**优先 A 或 B**。

### 3.1 Azure 密钥（`发音评测测试\` 和 `语音转文字\`）

1. 打开 https://portal.azure.com/
2. 创建资源 → 搜索 **Speech**（语音服务）→ 创建
3. 定价层选 **Free F0**（够测试用）
4. 建好后进入资源，左侧「**密钥和终结点**」，复制 **KEY 1** 和 **位置/区域**（如 `eastasia`）
5. 按上面填法 A 或 B 填入

> **同一个密钥通用**：发音评测和语音转写属于同一类资源（SpeechServices），
> 同一把密钥、同一个区域都能用，只是脚本里调用方式不同。

### 3.2 讯飞密钥（`讯飞评测测试\`）

讯飞要**企业实名**才能用语音评测。步骤：

1. 注册 https://www.xfyun.cn/ 并完成**企业实名认证**
2. 控制台 → 创建应用 → 添加服务 **语音评测（流式版）**
3. 在「服务接口认证信息」里拿到三样：`APPID` / `APIKey` / `APISecret`
4. 打开 `讯飞评测测试\xunfei_ise_test.py`，把顶部三行填上：
   ```python
   APP_ID     = "在这里填APPID"
   API_KEY    = "在这里填APIKey"
   API_SECRET = "在这里填APISecret"
   ```

> 讯飞这套是三个字段，和 Azure 的 `keys.txt` 格式不一样，所以**这个脚本只能改代码填**。
> （填完记得别把这个文件发给别人。）

**⚠️ 最容易踩的坑：APIKey 和 APISecret 填反**

这两个都是 **32 位字符串，肉眼完全分不出来**。填反了的症状是：

```
[错误] Handshake status 401 Unauthorized
{"message":"HMAC signature cannot be verified: apikey not found"}
```

看到 `apikey not found`，**八成就是填反了**，不是钥匙无效。

**不用猜**，跑一下自检：

```
双击  讯飞评测测试\check_key.bat    → 只做握手，验证三把钥匙对不对
双击  讯飞评测测试\swap_test.bat    → 直接把两个字段对调各试一次，告诉你该不该换
```

`swap_test.bat` 会给出明确结论，例如「★ 找到问题了：APIKey 和 APISecret 填反了」。
它只在内存里对调，**不会改你的文件**；确认后按提示手动互换那两行即可。

**其他也可能导致 401 的原因**（按概率）：

1. **APIKey / APISecret 填反**（最常见，用 `swap_test.bat` 一秒确认）
2. 应用**没有开通「语音评测（流式版）」**服务（控制台 → 我的应用 → 看服务列表）
3. 三把钥匙**来自不同应用**（要同一个应用里的三个字段）
4. 账号**未完成企业实名**（个人账号用不了语音评测）
5. 复制时**带了空格或换行**

`check_key.bat` 会先做格式体检（长度、是否含空格、是否还是占位符），再做握手。

## 4. 跑测试

**所有测试都是双击对应的 `.bat`**，不用敲任何命令。

### 4.1 发音评测（Azure，麦克风跟读）

```
双击  发音评测测试\run_pronunciation.bat
```

流程：屏幕显示标准句 → 你对着麦克风读一遍 → 自动出分。

想换测试的句子，打开 `test_pronunciation.py` 改这一行：
```python
REFERENCE_TEXT = "I want to improve my English pronunciation."
```

**✅ 成功的样子**：出现「逐词 / 逐音素明细」，形如
```
  词: pronunciation     40.0 分 [x] (Mispronunciation)
      /p/  100.0 分
      /ɹ/  35.0 分 <<< 不准
      ...
```
结果同时存到 `测试结果.json`（完整数据）和 `测试日志.txt`（可读日志）。

> **⚠️ 一个已知现象，不是 bug**：如果某个**整词**得分极低（如 14 分），
> 而且它**所有音素**都极低（如全部 7–21 分），这通常不是发音问题，是**时间对齐错位**
> —— 引擎把这句话和标准答案对错了位置。
> 判断方法：把那个词**放慢、加重、读清楚**再来一次，如果分数大幅上升，就说明是错位。

### 4.2 讯飞评测（麦克风跟读）

```
双击  讯飞评测测试\run_xunfei_ise.bat
```

流程：显示标准句 → 按回车开始录音 → 读完按回车结束 → 出结果。

**✅ 成功的样子**：屏幕打印「讯飞原始结果」+ 自动解析的 XML 树。
原始 XML 存在 `评测结果.xml`。

重点看结果里有没有这些字段：音素级明细、**连读**、**重读**、**停顿**、**升降调**。
有 → 说明这条路能同时管「发音 + 音变 + 节奏」；没有 → 换别家。

### 4.3 还原度测试（音频对音频，重点线路）

**准备**：把两个音频放进 `还原度测试\` 文件夹，命名必须是：

- `原音频.wav` —— 标准素材（native 录音）
- `模仿.wav` —— 你自己的模仿录音

> 格式要求：**wav**。16k 采样最好，但脚本会自动重采样，其他采样率也行。
> 其他格式（mp3/m4a）请先用工具转成 wav。

然后：

```
双击  还原度测试\run_rhythm.bat     → 节奏 / 语调对比
双击  还原度测试\run_phoneme.bat    → 音素序列对比
```

**`run_rhythm.bat` 输出**：总时长差、停顿位置和数量、DTW 节奏相似度（0–100），
并生成 **`节奏对比.png`**（上下两条曲线，灰色块标停顿，紫线是音高）。

**`run_phoneme.bat` 输出**：两条音素序列对齐后的差异，形如
```
  [替换] 应该读 θ  →  你读成了 s
  [缺失] 你没读 t ə （原音频里有）
  [多余] 你多读了 ə
```
结果存 `音素对比.json`。

> **首次运行 `run_phoneme.bat` 会下载音素模型（约 1.2GB）**，慢一次，之后就快了。
> 模型存在 `还原度测试\models\` 下。
>
> **怎么看结果**：
> - `[缺失]/[多余]` 经常出现在**连读、弱化、吞音**处 —— 这就是「音变还原度」
> - `[替换]` 是某个音发错了（如 θ 读成 s）
> - ⚠️ 音素识别模型对**学习者发音**的判断未必 100% 准，先看**趋势**，别抠单个音

### 4.4 语音转文字（早期链路 + 麦克风排查）

```
双击  语音转文字\run_transcribe.bat     → 实时中文转写，结果追加到 听记笔记.txt
双击  语音转文字\run_diag.bat           → 链路诊断（网络/密钥/SDK 通道逐项查）
双击  语音转文字\run_mictest.bat        → 麦克风通道测试（不需要说话）
双击  语音转文字\run_miclevel.bat       → 麦克风音量检测（对着麦大声说 10 秒）
双击  语音转文字\run_miccheck.bat       → 读注册表查麦克风权限
```

**麦克风出问题时的排查顺序**：`run_miccheck.bat`（有没有权限）
→ `run_miclevel.bat`（收到声音没）→ `run_diag.bat`（网络通不通）。

## 5. 包的结构

```
AI Memory Card\
├── 安装说明.md                ← 本文件
├── install_deps.bat           ← 双击这个装依赖（第一步）
├── requirements.txt           ← 依赖清单（install_deps.bat 会读它）
├── _runpy.bat                 ← 公共启动器，被其他 .bat 调用，别单独跑
│
├── 讯飞评测测试\
│   ├── run_xunfei_ise.bat     ← 入口：跑评测
│   ├── check_key.bat          ← 入口：只验钥匙（不录音，推荐先跑这个）
│   ├── swap_test.bat          ← 入口：判断 APIKey/APISecret 是否填反
│   ├── xunfei_ise_test.py
│   ├── check_xunfei_key.py
│   └── swap_test.py
│
├── 还原度测试\
│   ├── 一键跑还原度.bat        ← 入口：音素→节奏→综合 三步一把跑
│   ├── run_rhythm.bat         ← 入口：节奏/语调对比
│   ├── run_phoneme.bat        ← 入口：音素对比（发音+音变）
│   ├── compare_rhythm.py
│   ├── compare_phoneme.py
│   ├── overall_score.py       ← 综合评分 + 纠音报告（读前两步的 json）
│   ├── 讯飞转写测试.py         ← 可选：讯飞 LFASR 打词级时间戳
│   ├── 讯飞配置.json           ← 可选：LFASR 的 appid/secret（含密钥）
│   ├── 原音频.wav              ← 你自己放
│   ├── 模仿.wav                ← 你自己放
│   └── models\                ← 首次跑自动下载的模型（约 1.2GB）
│
└── archive\                   ← 归档区（当前主线不用，留作备用）
    ├── 发音评测测试\            ← Azure 逐音素打分（早期方案）
    └── 语音转文字\              ← 实时转写 + 麦克风诊断工具
```

**包内不含的东西（刻意排除）**：

- `.venv\`（环境）：体积 3–4 GB，且路径写死在这台机器上，**换台电脑根本不能用**，必须现装
- `models\`（音素模型）：1.2 GB，脚本会在首次运行时自动下载
- **任何密钥**：全部替换为占位符

## 5.5 打包清单（打包的人看）

要发给别人时，**在 `AI Memory Card\` 里把下面这些删掉/排除**，剩下的才是干净的包：

| 要排除 | 为什么 |
|---|---|
| `.venv\` | 3–4 GB，且不可移植 |
| `还原度测试\models\` | 1.2 GB，脚本会自己下 |
| `**\__pycache__\` | Python 缓存，无用 |
| `**\测试日志.txt` | 你的运行日志，含时间戳 |
| `**\测试结果.json` | 你的评测数据 |
| `语音转文字\runlog.txt` | 你的运行日志 |
| `语音转文字\听记笔记.txt` | **含你录的语音内容** |
| `**\keys.txt` | **密钥，绝对不能带** |
| `**\评测结果.xml`、`**\音素对比.json`、`**\节奏对比.png` | 你的运行产物 |
| `还原度测试\原音频.wav`、`模仿.wav` | 你的测试素材（除非想一起分享） |

**另一种做法**：不删原件，只把需要的文件**复制**到一个新文件夹再压缩。
这样你自己的测试环境不受影响。

**⚠️ 压缩前最后检查一遍**：确认包内**没有任何 `keys.txt`**，
并且 `test_pronunciation.py`、`live_transcribe.py` 里是
`SPEECH_KEY = "在这里填你的KEY"` 这种占位符，而不是一长串真密钥。

## 6. 排坑（照着查）

### 6.1 「python 不是内部或外部命令」

装 Python 时漏了勾 `Add Python to PATH`。重装一遍，勾上。
或者手动把 Python 安装目录加进系统环境变量 PATH。

### 6.2 装依赖报 `from versions: none` / 一直超时

**网络问题**，不是包坏了。`install_deps.bat` 已用清华镜像，如果还失败：

- 换个网络试试（手机热点）
- 或者手动指定镜像：
  ```
  .venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
  ```

### 6.3 音素对比报 `xxx.json is not a valid JSON file`

模型文件下载不完整（有 0 字节的坏文件）。**删掉整个 `还原度测试\models\` 文件夹，重跑一次。**

### 6.4 音素对比卡在下载不动

脚本默认走 `hf-mirror.com`（国内镜像），因为 `huggingface.co` 在国内常常连不上。
如果镜像也慢：

- 确认网络能访问 https://hf-mirror.com
- 想换成官方站：运行前设环境变量 `HF_ENDPOINT=https://huggingface.co`

### 6.5 音素对比报缺 `phonemizer`

**不该出现这个错**。脚本已经绕开了 `phonemizer`（直接读模型的 `vocab.json` 解码），
因为 `phonemizer` 在 Windows 上还要额外装 `espeak-ng` 本机库，很麻烦。
如果真报了，说明用的是旧版脚本，找技术同学要最新的 `compare_phoneme.py`。

### 6.6 中文显示成方块（图中文字）

`matplotlib` 找不到中文字体。脚本已指定 `Microsoft YaHei` / `SimHei`，
Windows 一般都有。如果是精简版系统缺字体，装一下「微软雅黑」即可。

### 6.7 麦克风录不到声音

按顺序查：

1. `run_miccheck.bat` —— 权限开没开（Windows 设置 → 隐私 → 麦克风）
2. `run_miclevel.bat` —— 对着麦大声说，看哪个设备 RMS 值高
3. `run_mictest.bat` —— 不需要说话，验证通道能否建立
4. 检查：麦克风插好没 / 系统是否静音 / 离嘴是不是太远

### 6.8 讯飞报鉴权失败

**先跑 `check_key.bat` 和 `swap_test.bat`**，不要凭感觉猜。

- **`apikey not found`** → 90% 是 **APIKey 和 APISecret 填反了**（两个都是 32 位，看不出差别）。
  用 `swap_test.bat` 确认，然后互换那两行。
- 确认**账号已完成企业实名**（个人账号用不了语音评测）
- 确认三把钥匙从「**语音评测（流式版）**」这个服务下复制，且**来自同一个应用**
- 系统时间不准也会导致鉴权失败（签名里带时间戳），校准一下系统时间

### 6.9 bat 报 `script not found: xxx.py`

脚本路径没对上。检查 `.bat` 和 `.py` 是否在**同一个文件夹**里。

### 6.10 报 `No module named 'numpy'` 之类

找到了 Python，但它**没装依赖**。启动器会自动跳过这种 Python 去找下一个，
实在找不到才报错。解决办法：**双击 `install_deps.bat`** 装一遍。

> 说明：启动器不是简单地「用 PATH 里的第一个 python」，而是**逐个测试**
> 「这个 python 能不能 import numpy 和 sounddevice」，用第一个合格的。
> 所以系统里有多个 Python 也不会用错。

## 7. 名词小词典

| 词 | 一句话解释 |
|---|---|
| **音素（Phoneme）** | 发音的最小单位，一个音标符号。`p` `ɹ` `ə` 各是一个音素 |
| **IPA** | 国际音标，就是 `/p/` `/ɹ/` 这种写法。脚本里用它显示音素 |
| **音变** | 口语里连读、弱化、浊化、吞音的总称。如 `want to` 常读成 `wanna` |
| **节奏 / 语调** | 语速、停顿、重音、音高升降。DTW 用来算两段节奏有多像 |
| **DTW** | 动态时间规整。两段音频长短不同，用它拉伸对齐后再比差异 |
| **发音评测** | 逐音素打分，判断发音准不准（区别于「转写」只判断说了什么） |
| **正解 / 对齐错位** | 引擎把读音和标准答案对错了位置，导致分数虚低，不是发音问题 |
| **venv** | Python 的虚拟环境。把依赖装在一个独立文件夹里，不污染系统 |

## 8. 让 AI 帮你装（给 AI 助手的指令）

如果你是 AI 助手，请按以下顺序操作，**每步验证后再进行下一步**：

1. **检查 Python**：执行 `python --version`。
   - 成功判据：输出 `Python 3.1x.x`（≥3.11）
   - 失败：提示用户去 python.org 下载安装，强调勾选 `Add Python to PATH`，**然后停下等用户**

2. **装依赖**：执行 `install_deps.bat`（Windows）。
   - 成功判据：输出含 `all OK` 和 `DONE`
   - 失败：若是网络超时，重跑一次；若仍失败，改用镜像手动 pip

3. **验证环境**：执行 `.venv\Scripts\python.exe -c "import azure.cognitiveservices.speech, websocket, numpy, sounddevice, soundfile, torch, transformers, matplotlib; print('OK')"`
   - 成功判据：打印 `OK`

4. **确认密钥**：询问用户要测哪条线路，帮忙创建对应的 `keys.txt`。
   - 注意：讯飞那条线路只能改 `xunfei_ise_test.py` 顶部三行，格式不同
   - **不要把密钥写进任何会外发的文件**

5. **跑测试**：按第 4 节，让用户双击对应 `.bat`。
   - 需要用户**本人**完成的操作：对着麦克风说话、提供音频文件、注册账号拿密钥
   - 这些你代替不了，明确告诉用户「这一步只能你来」

6. **遇到报错**：对照第 6 节。特别注意：
   - `is not a valid JSON file` → 删 `models\` 重下
   - `from versions: none` → 网络问题，走镜像
   - 整词所有音素都低分 → 对齐错位，不是 bug

**不要做的事**：不要试图打包或复制 `.venv` 目录（不可移植）；
不要下载模型手动放进包（脚本会自动下）；不要把密钥硬编码进脚本。
