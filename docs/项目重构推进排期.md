## 1. 量化口径

**单位 = 1 个「可验收工作块」**：一件能当场跑一遍 / 听一遍、且有明确通过标准的活。

- 不是"我写完就算"，是"**大法师验完才算**"。
- 整轮 = **12 个工作块**，每块约占 **8%**。
- 时间预算（09-23 大法师确认）：**每天约 2 小时**，有时间可 2 小时以上 → **每天 2 块 → 6 天**。
- 三个易卡点（块 4 / 5 / 8）任一卡住，顺延到 **8 天**。

**推进纪律**：第一块超时，第二块顺延，**不做两块硬压**。

## 5. 双人对话场景（09-23 定案：素材预标注换人点，**不做声纹分离**）

### 5.1 问题是什么

09-23 大法师确认：**给他提供的文本，大部分是双人对话（含抢答），少部分是单人朗读。**

而计划书里有一处**未解决的口径冲突**：

- **§5 风险 7**：两人对话场景下**全句统计量不成立**，重音/节奏**必须先分段**再算统计量；
- **§2.6 整节**（邻域法、中位数归一、半音化）**全部建立在全句统计量上**；
- **§7 待办**把「说话人自动分离 / 切句」划到了**下一轮**。

→ **结论：大法师 80% 的真实输入，恰好落在本轮计划覆盖不到的部分。** 若不管，块 10/11 在双人音频上出来的重音分、节奏分会是「数字有、参考性不明」—— 这正是本项目最怕的静默失真（参见 `overall_score.py` 用 `.get(k, 0)` 兜底导致报告恒打印 0 的教训）。

### 5.2 为什么双人不准（已向大法师讲清）

重音判定 = 把每个词块跟**这一侧整段音频的基准**比，明显高出算「突出」。

> ⚠️ **修正 09-23 初稿的口误**：尺度是「**整段音频（该侧）**」，**不是「一句话」**。
> 依据：代码 docstring 原文「各侧自比：某块 响度/音高 超过【**本侧**】均值 × x」。
> 另：现网用的是**均值**，「中位数」是计划书 §2.1 要改成的 —— 两层都在计划书里：
> ① 归一化用**该侧全局中位数**（`median_F0_s`，消性别）② 判定用**前后邻块中位数**。
> 代码里**没有「句子」这一层**。

- 单人：中位数 = 他自己的基准 ✓
- 双人：中位数 = **两个人嗓子的混合平均值**，既不是 A 的基准也不是 B 的基准 ✗
  （男声均值约 212 Hz / 女声约 364 Hz，差近一倍）

→ 后果：低嗓的一方**全判「不突出」**、高嗓的一方**全判「突出」**，与听感相反。

- **影响面**：只影响**重音**与**节奏**两个维度；**发音 / 音变不受影响**（逐音素比对，不用句级统计量）。
- **「含抢答」更糟**：抢答 = 两人**重叠说话**，连「哪段是谁」都分不出（沉默处还能按静音切，重叠处波形糊在一起）→ 不是判不准，是**没地方切**。
- **解法 = 分段**：切成「A 单独说的段 / B 单独说的段」，**每段自己算自己的中位数**。分段后双人也准。

### 5.4 实据（09-23 核实）

**① 代码口径**（`compare_rhythm.py:379` docstring 原文）
> 「各侧自比：某块 响度/音高 超过【**本侧**】均值 × x 即算突出」

→ 尺度 = **整段音频（该侧）**；**没有「句子」这一层**；且现网用的是**均值**（非中位数）。

**② 素材形态**（查 `_t_xf_words.json` 讯飞缓存）

| 角色 | 词 | 时间 | 换人处 |
| --- | --- | --- | --- |
| A（问） | so / Where / are / you / working / now / Terry（7 词） | 740–2810ms | 原音频：`Terry`→`oh` 间隔 **10ms**（讯飞未给停顿） |
| B（答） | oh / im / still / at / the / bank（6 词） | 2820–4730ms | **模仿：`Terry`→`oh` = 280ms**（全曲唯一停顿） |

→ 两侧**词序完全一致（13 对 13）**；换人点在**第 7 / 8 词之间**。

**③ 大法师 09-23 确认（两个关键事实）**
- 原音频（标准素材）= **母语者 A / B 一问一答**，**确实是两个人**
- 模仿侧 = **他一个人读整段**（分饰两角）

**→ 三条推论全部成立：**

| # | 推论 | 意义 |
| --- | --- | --- |
| 1 | **「按静音切句」这条路不存在** | 就一段，没有多句可切 |
| 2 | **只有原音频侧被污染**（A / B 两人混算中位数）；模仿侧一人读 → **中位数本来干净** | 工作量**减半** |
| 3 | **原音频是预置标准素材、固定不变** | 换人点**标一次、永久复用**，且**可以人工标**（准确率 100%） |

再加一条杠杆：**两侧词序一致** → 原音频标的换人点**按词序直接映射到模仿侧**。

### 5.5 定案方案：换人点从「参考文本」标，**既不做声纹分离、也不从音频猜**

> ⚠️ **本节 09-23 二次修正**。原稿写"人工标，或自动出声学候选后人工确认"。
> 大法师指出**讯飞时间戳已弃用（决策 4）**，顺着这个方向重推，结论是：
> **换人点根本不该从音频来，应该从参考文本（剧本）来** —— 与决策 3「词归属来自参考文本、不从音频猜」**完全同构**。
> 原方案里"从音频检测换人点"的思路就此作废。

**做法**

1. **换人点 = 参考文本上的一个「角色边界」**（本例：第 7 个词 `Terry` 之后轮到另一人）
   - 来源：**素材自带的剧本 / 参考文本**（一问一答，谁说什么话本来已知）
   - **纯文字层，零时间依赖 —— 不碰时间戳，更不碰讯飞**
2. **写进离线预生成产物**：决策 3 已定 `参考音素.json` 要出 `词边界:[{word,a,b}]`，
   在同一个结构里加一个 `角色` 字段即可：

   ```json
   {"词边界":[{"word":"so","a":0,"b":1,"角色":"A"}, ...,
               {"word":"oh","a":7,"b":8,"角色":"B"}, ...]}
   ```

3. **模仿侧不单独处理**：按**词序位置**沿用原音频的角色边界（两侧词序一致）
4. **算统计量**：按角色把词块**分组**，**每组自己算自己的中位数**，组内判突出，再合并

**收益**

- 原估 **+4~6 天** 的 diarization 子项目 **取消**
- **实验 D 一并取消**（不再需要检测换人点）→ **块 1 少一件事**
- 成本降到「参考文本加角色标注 + 分组计算逻辑」：**离线、零新依赖、无许可证风险**

**为什么两侧都用同一套角色边界**：原音频侧必须分组（两人）；模仿侧虽一人读、中位数干净，但 `重音位置` 分是**比两侧的突出位置** —— 两侧分组口径必须对称，否则比不对。

**⚠️ 连带坑（新发现）**：换人处**天然带停顿**（本例模仿侧 `Terry` 后 280ms）。
阶段 4.5.2 的「停顿位置分」若照旧把两侧 gap 拿来比，**换人处的停顿会被误判成「多余停顿」而扣分**。
→ 分组后必须**把换人处的 gap 排除出停顿判定**，或改标为「预期停顿」。
