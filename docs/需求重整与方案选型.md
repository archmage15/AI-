## 一、需求重整（按优先级）

### 1. 产品目标
辅助**成人日常英文口语自学**。
核心学习循环：**听原音频 → 模仿原音频**。

### 2. 硬性要求（不能丢）
必须能指出三类问题，优先级从高到低：

| 序 | 类别 | 内容 |
|---|---|---|
| 1 | **发音** | 音素准不准（θ / r / 长短音…） |
| 2 | **音变** | 连读 / 弱化 / 浊化 / 吞音 |
| 3 | **节奏** | 韵律 / 停顿 / 重音 |

> 定调：「英文口语的基础就是发音和音变，再其次是节奏。」

### 3. 流程约束
- 学生学习时**全程不看文本**。
- 文本仅为"听不懂时的拐杖"，且写**标准形式**（`want to`），**不是** `wanna`。
- AI 的转写**不展示给学生**。
- **不能逐句手工标注**（内容量大，不可行）。

### 4. 阶段与边界
- 当前只做**语音**；口型 / 视觉为后期。
- 现阶段走**外接调用的 API**。
- 处于**选型测试阶段**：目的是选出合适的路线与 API。

## 二、概念框架：两把尺子——还原度（目的）与达标度（参考）

### 2.1 主次关系（先定死这一条）

> **我们练的是"模仿"。只有模仿地道的语音，才有可能学出地道的口语。**
> 所以**还原度是把的东西**——像不像**那段原音频**，这是目的。
> **达标度只是参考**——符不符合**字典标准音**，不是我们要的目标。

这两者**比的对象根本不同**，所以不是"两个维度拼一起"，而是**有主有副**：

| | 尺子 | 跟谁比 | 地位 |
|---|---|---|---|
| **主线** | **还原度** | **原音频**（这段素材本人怎么读的） | **目的**，最终判据 |
| 参考 | 达标度 | 字典 / 标准音（TTS 或通用发音库） | **参考**，辅助提示 |

**为什么必须分清**：一段地道口语里，`want to` 读成 `wanna`、`to` 几乎不发音，在**字典标准**下会被扣分（甚至判"漏读"），但对照**原音频**恰恰是**还原得很像**。若把达标度当判据，会把**最地道的部分当成错误纠正**——越练越偏。两个尺子打架时，**还原度优先**。

### 2.2 怎么量这两个东西（两把"量尺"）

主次定了，再谈**怎么量**。判断"像不像"，需要覆盖两类信息：

| 量尺 | 管什么 | 答的是 |
|---|---|---|
| **① 音素** | 发音 **+** 音变 | "音对不对" |
| **② 节奏 / 语调** | 节奏（韵律、停顿、重音） | "韵律像不像" |

- **为什么"音素"一把量尺能管两件事**：音变本质上就是**"音素序列变了"**——`wanna` vs `want to` = 少了 `/t u/`；连读 = 音素黏连；浊化 = `/s/` 变 `/z/`。所以音素序列的对比，天然把 **发音 + 音变** 一起覆盖。
- 这两把量尺**互补、不可互替**：音素答"音对不对"，节奏答"韵律像不像"。
- **注意**：音量得准，不等于比得对。**量尺只负责"读出数据"，判据由 2.1 决定**——同样的音素数据，跟字典比是达标度，跟原音频比才是还原度。
- **概念与实现解耦**：先把"尺子"和"判据"定死（已定），再定"每把量尺由哪个服务实现"（见第四、五节）。这样换供应商也不伤筋动骨。

## 三、方案评估：两条路线

### 3.1 三个候选

| 路线 | 比的对象 | 发音 | 音变 | 节奏 | 免标注 | 避音色 |
|---|---|---|---|---|---|---|
| **甲** 专业口语评测 API | **字典** | ✅ | ✅ | ✅ | ✅ | ✅ |
| **乙** 自建音素识别对比 | **可指定（含原音频）** | ✅ | ✅ | 需自做 | ✅ | ✅ |
| **丙** 直接比录音相似度 | 原音频 | ❌ 混音色 | ⚠️ | ✅ | ✅ | ❌ |

### 3.2 结论

- **丙直接排除**：虽然它也是"音频对音频"，但会被**音色差异**污染——测出来一半是"你俩嗓音像不像"，不是"发音像不像"。
- **乙是唯一能守住主线（还原度）的路线**：它把声音**符号化**成音素序列，音色在这步被丢掉；符号序列**可以跟任意一方比**——**跟原音频比，就是还原度**。这正是我们最终要的能力。
- **甲不能当判据，但是现阶段最有价值的第一步**：它比的是**字典**，所以出来的是**达标度**——按 2.1，这只是**参考**，不是目的。但它**音素 + 音变 + 节奏一把抓、零建模成本、有免费额度**，先跑通它能让我们**立刻拿到真实的音素级/音变/韵律数据**，验证"评测方到底能不能听出学习者的发音"（见 3.3）。
- **所以现阶段的关系不是二者择一**：**甲先跑起来，拿到数据；乙代表主线的落地方向。**

### 3.3 共同前提（须实测）
- 无论甲或乙，都压着同一个问题：**识别端能不能准确"听出"学习者的发音**（而不是把错音"修"回正确的）。
- 精细区分（弹舌 /ɾ/ vs /t/、连读边界）最考验这一点。
- **甲已用一句实测跑通**（见第五节），数据符合预期；**乙尚未开跑**（脚本已备好，缺 `原音频.wav` + `模仿.wav` 两段素材）。

## 四、外接 API 选型建议

### 4.1 关键认识：专用「口语评测」API 本就把连读当评测项
通用语音识别（ASR）会把口语**归一化**，抹掉音变特征。
但**专做口语评测的 API 大多内置连读 / 弱读检测**，直接把它当成评测维度 →
**所以不必自己搞"口语转写"那套 hack。**

### 4.2 候选对比
| 服务 | 音素级 | 音变（连读） | 节奏 / 语调 | 备注 |
|---|---|---|---|---|
| **讯飞 语音评测 ISE** | ✅ 音节/音素级 | ✅ **显式：连读检错** | ✅ 停顿 / 重读 / 升降调检错 | 教育标配、中文文档、极便宜 |
| **Speechace** | ✅ 词/音节/音素 | ✅ **显式：linking 检测** | ✅ fluency + intonation | 国际专业级、有新加坡节点、支持自定义音素 |
| **SpeechSuper** | ✅ | ✅ liaison | ✅ rhythm / stress / tone | 价格透明 |
| **Azure PA** | ✅ 音素级 | ⚠️ 无专门连读项 | ✅ prosody（仅美音） | 已有、成熟基线 |
| **腾讯云 SOE** | ✅ 音素级 | ⚠️ | ✅ 重音等 | 中文厂商、支持音素标注 |

### 4.3 推荐

> 提醒：以下服务**全部是"跟字典比"**的评测 API，产出的是**达标度（参考）**。选它们是为了**取数据、验原理**，不是当最终判官。

1. **首推：讯飞语音评测（ISE 流式版）** —— 已实测跑通，见第五节
   - 教育行业标配（连续 8 年为中高考英语听说考试提供评测）；
   - 返回**音素级 + 连读/重读/停顿/句末升降调检错**——正好覆盖**音变 + 节奏**；
   - 便宜（约 **¥15–60 / 万次**）；**企业实名认证送 10 万次 / 90 天**，测试阶段**零成本**；
   - 中文文档、中文支持、国内低延迟。
2. **次推 / 对照：Speechace**
   - 国际专业级，**connected speech / linking 检测**明确，`markup=arpa_mark` 可**自定义音素**；
   - 三把尺子全覆盖，有**新加坡节点**；需商务报价。
3. **保留：Azure PA** 作**基线对照**（连读项弱）。

### 4.4 注意事项
- 各家"连读检测"在**学习者**身上的可靠性**仍需实测**。
- 讯飞流式版目前只返回 **XML**（JSON 待支持）。
- 一个 API 往往**同时给"音素"和"节奏/语调"两把量尺** → 不必拼两个服务。
- **这些 API 都不提供"跟原音频比"的能力**。要拿还原度，必须走乙路线（自建音素序列对比，见第五节）。

## 五、实测记录：讯飞 ISE 已跑通（2026-09-17）

**素材**：`I want to improve my English pronunciation.`
**状态**：脚本 `讯飞评测测试\xunfei_ise_test.py` 跑通，返回完整 XML 并已解析成中文结论。

### 5.1 它一次返回了三样东西（超出预期）

| 我们需要的 | 讯飞给的字段 | 说明 |
|---|---|---|
| **音素级** | `<phone content="ah">` | 拆到音节内部的单个音 |
| **音变 / 漏读检错** | `dp_message` / `serr_msg` / `gwpp` | 整词没读 / 音节读错 / 发音偏离度 |
| **节奏 / 语调** | `pitch`（音高曲线数组）、`syll_accent`（音节重音） | 可画曲线、可看重音位置 |

**结论：一家就覆盖了 2.2 的两把量尺**，不必拼两个服务。

### 5.2 实测数字（5 分制，已换算百分制）

| 项 | 得分 |
|---|---|
| 综合 | **74.9 / 100** |
| 发音准确度 | 85.3 / 100 |
| 流利度 | 92.9 / 100 |
| 完整度 | 85.7 / 100 |

**它标出的问题词**：
```
to                 0.0 分  ← 没读 / 漏读
    └ 音节 [t uw]    0.0 分
pronunciation     69.4 分  ← 读错了
    └ 音节 [n ah n]   57.6 分   · 音 [ah] 偏离明显
    └ 音节 [ey]       36.8 分
english           70.2 分  ← 读错了
    └ 音节 [ih ng]    36.8 分
```

### 5.3 这组数据说明了什么（关键）

`to` 被判 **0 分 / 没读**——**这恰恰是最有价值的一条**。

- 在**字典标准**下：`to` 没读出来 = 严重错误、扣大分。
- 在**地道口语**里：`want to` → `wanna`，`to` 本来就几乎不发音。

**这就是 2.1 说的"两把尺子打架"的真实案例。** 它同时说明两件事：

1. **讯飞这套是能用的**——它真的听出了音素级偏差（`[ah]`、`[ih ng]` 偏离明显），识别端没在"猜词"，我们 3.3 的担心初步解除。
2. **它绝不能当判据**——它比的是字典。**你模仿得很像原音频，它照样可能给你低分**。所以它是**参考（数据源）**，判据必须来自**跟原音频比**。

> **一句话**：讯飞负责告诉我们"音素长什么样"，不负责告诉我们"像不像原音频"。像不像，得让乙路线（音素序列 vs 原音频的音素序列）来说。

### 5.4 已知局限
- 只返回 **XML**（JSON 待官方支持），需自行解析；
- 判定"是不是照读原文"，若不像是照读会给 0 分并标 `is_rejected`，此时分数仅供参考；
- **它不提供原音频**，无法做还原度对比。

## 六、视觉通道（后期）

视觉是**补充**，不是替代。它看得见"口型"，看不见"声音"。

| 视觉**强**（看得到） | 视觉**盲**（看不到） |
|---|---|
| 咬舌音 /θ/ /ð/（舌尖伸齿间） | 浊化（声带振动，看不到） |
| 唇齿音 /f/ /v/（下唇贴上齿） | 连读（属时间，不属口型） |
| 圆唇 /uː/ /w/、展唇 /iː/ | 吞音 |
| 口型开合（下颌，部分） | 舌位（大部分藏在口腔内）、元音细节 |

- 视觉**正好补上中国学习者最痛的几个"看得见的音"**（咬舌、圆唇、唇齿）；
- 但对**音变（连读 / 弱化 / 吞音）和浊化无能为力**——这些只能靠音频。

## 七、下一步实验

### 7.1 甲路线（讯飞）—— 已跑通，继续攒数据
**目标**：确认它的稳定性与边界。
1. 换更多**带连读 / 弱化**的句子跑，看是否稳定返回音变检错；
2. 故意读错（比如 `th` 读成 `s`），看它能否抓出来；
3. 重点观察：**`to` 这类"地道弱读"被误判的频率有多高**——这直接决定它能当多重的参考。

### 7.2 乙路线（还原度主线）—— 待开跑 ★
**目标**：验证"音素序列 vs 音素序列"能否真正测出**还原度**。
**前置条件**：两段音频
- `原音频.wav`：地道的原素材（母语者或标准示范）
- `模仿.wav`：学习者跟着读的录音

**做法**：两个脚本已写好（`还原度测试\compare_phoneme.py` / `compare_rhythm.py`）
1. 各自转成音素序列（音色在此步被丢弃）；
2. **逐音比对**，算出"漏了哪些音、多了哪些音、哪些音不同"；
3. `compare_rhythm.py` 再比节奏（音高曲线、停顿位置）。

**判定**：**能指出"哪个音素不像原音频"，就说明主线能落地。**

> 顺序上：**甲先跑（成本低、马上有数据），乙跟上（守住主线）。**
