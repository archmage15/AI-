# AI 录音卡 · 项目说明

> 本文档写给「负责实现的 AI」看，目标是读完即可明确要造什么、怎么验收。

## 1. 一句话定位
一个辅助「成人日常英文口语自学」的软硬件工具：用户跟读标准素材，系统通过麦克风判定发音哪些音不准，通过摄像头在录后回看时标出哪些音的口型不到位，并给出改进示范。

## 2. 目标用户 / 场景
- **谁**：成人自学者，零基础到初级，自己练、自己纠错。
- **场景**：居家 / 通勤碎片时间，对着设备跟读练习，练完看报告。

## 3. 用户使用流程（时序）
1. 用户在软件里选一条练习素材（一句 / 一段英文，带标准音频 + 文本）。
2. 点「开始」，硬件收音、摄像头录视频；软件先播标准音，用户跟读。
3. 录完自动生成两份分析：发音评分 + 口型分析。
4. 用户回看：原视频带时间戳标注「此处口型不到位」+ 逐音素发音表 + 改进建议（含正确示范音 / 口型图）。

## 4. 核心功能模块（输入 → 处理 → 输出）

| 模块 | 输入 | 处理（AI 要干的活） | 输出 |
|---|---|---|---|
| 发音分析 | 标准音频 + 文本；用户跟读音频 | 把两段按音素对齐到时间轴，逐音素算相似度，判对 / 错 / 接近 | 逐音素表（音素 · 对错 · 得分）+ 整句分 |
| 口型分析（录后） | 用户说话视频 | 提取嘴部关键点（开合度 / 宽高比 / 嘴角位移），与标准口型库逐音素对比 | 逐音素口型偏差 + 视频叠加标注 |
| 反馈合成 | 上面两份结果 | 生成改进建议：每个错音给「正确发音要点 + 标准口型图 / 示范音」 | 一份可回看报告 |

## 5. 两个关键定义（避免歧义）
- **跟读对比** = 不是「随便说打分」，而是「系统播标准音 → 用户照着读 → 逐音素比差距」。必须有标准音素素材库（每个音素带标准音频 + 参考口型）。
- **录后分析** = 口型不在说话时实时标，而是录完回看视频时，在对应时间点标红「这个音口型没到位」。

## 6. 硬件 / 软件边界
- **硬件只做**：高保真收音模块 + 一个录制键 + 状态灯。不跑 AI。
- **软件做**：全部对齐、评分、口型检测、UI、报告。
- **MVP 建议**：先用普通 USB 麦 + 电脑摄像头跑通软件闭环，硬件作为二期。

## 7. 验收标准（怎么算做对了）
- 给一句标准素材，用户故意读错 2 个音 → 报告能标出这 2 个音「不准」且位置正确。
- 用户故意把某个圆唇音（如 /u:/）读成不圆唇 → 回看视频对应时间点被标「口型不到位」。
- 每条错误都附一条可操作的改进建议。

## 8. 待确认的开放问题（定了再收口）
- 软件跑在哪：网页 / 桌面 / 手机？
- 标准素材库从哪来：自建、用公开数据集、还是接现有 API（如有道 / ELSA 类）？
- 能否用云端 AI，还是必须离线跑（隐私）？
- 「卡」具体指什么：USB 外设、PCIe 录音卡、还是独立小设备？

## 9. 技术路线与关键结论（2026-09-17 补充）

### 9.1 核心判断：发音评测 ≠ 语音转写
- **语音转写（STT）**：只知道你说**了什么词**，判不出**说得准不准**。
- **发音评测（Pronunciation Assessment）**：能逐音素打分、标出错音。
- 两者是**同一个 Azure SpeechServices 资源、同一把密钥**，只是代码里的用法不同，不需要换服务。

### 9.2 三层评测体系（按重要性排序）
英文口语的基础顺序：**发音 > 音变 > 节奏**。三层分别用不同"参照物"：

| 层 | 评什么 | 参照物 | 现状 |
|---|---|---|---|
| 第一层 · 发音 | 音素准不准 | 字典标准文本 | 成熟可靠 |
| 第二层 · 音变 | 连读 / 弱化 / 浊化 / 吞音 | 原音频的"口语转写"（**内部参照**） | 机制可行，待实测 |
| 第三层 · 节奏 | 韵律 / 停顿 / 重音 | 原音频本身（音频对音频） | 可行，不碰文本 |

### 9.3 第二层「音变」的关键机制（极性翻转）
- 把 native **实际读的**弱化形式写成参考文本，喂给评测。
  例：标准文本 `I want to improve...` → native 实际读 `I wanna improve...` → 参考文本就写 `I wanna improve...`。
- 效果：学生**读出弱化 → 匹配、高分**；读成字正腔圆的 "want to" → **反被判"没弱化"**。极性翻转，正好能抓音变。
- 关键：这份"口语转写"是**内部参照，学生永远看不到**，因此**不破坏"听→模仿、全程不看文本"的学习流程**。
- 代价：内容需**人工标注一次**（每句）。

### 9.4 已知边界（诚实标注）
- 节奏对比抓不到"具体哪个音吞了"的音段细节 → 由第一、二层补足。
- 音变参照对**单词级弱化**（wanna / gonna / gotta / kinda）好使；对**跨词连读**（an apple → /ənæpəl/）较别扭（连读没法靠换拼写表达）。
- **未验证项**：Azure 对弱化形式的评分准确性尚未实测，需先跑一次验证实验。

### 9.5 下一步验证实验
把测试脚本的参考文本从 `want to` 改为 `wanna`，重读一遍：
- 读成 "wanna" 分数上升 → 第二层机制成立；
- 分数不动 → 说明还有坑，另寻方案。
